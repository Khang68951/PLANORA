01 / OVERVIEW

Planning without the technical friction.

Planora brings a dashboard, monthly calendar, and task/deadline list together in one responsive interface backed by PostgreSQL.

1Primary user type
3Core product views
4JSON API operations
6Seeded demo items
Executive summary

One source of truth for the days ahead

The MVP stores tasks and deadlines in one constrained PostgreSQL table, then derives calendar placement and urgency summaries from that same data. Users can create, search, filter, complete, reopen, and remove items.

Current state

Working vertical slice

The optimized Next.js build passes. Local PostgreSQL provisioning and schema creation are automated, while live database smoke testing remains to be completed on a machine with Docker or PostgreSQL available.

02 / PROBLEM

Important dates disappear into scattered lists.

People need a simple visual answer to three questions: what is due, when is it due, and what needs attention now?

01

Primary user

A student or everyday planner who wants a calendar but should not need database, coding, or configuration knowledge.

02

Core friction

Separate task lists and calendars make urgency harder to see, while technical installation steps can make otherwise simple tools inaccessible.

03

MVP boundary

Single-user local planning is in scope. Accounts, sharing, reminders, recurring events, external sync, and production hosting are not yet included.

08 / IMPLEMENTATION

One model, three useful perspectives.

The browser receives one ordered collection; each view transforms it for a different planning question while mutations return to the same validated API.

Dashboard

Four summary cards and a priority queue expose today, the next seven days, overdue work, and completion.

Calendar + list

Month navigation, day-based creation, filtering, search, completion, reopening, and deletion.

Data layer

Parameterized SQL, constrained values, UUID keys, indexes, HTTP validation, and idempotent setup.

11 / REFLECTION

Be clear about limits and learning.

A strong report distinguishes what was achieved, what remains limited, what changed during development, and what should happen next.

Limitations

Local single-user MVP

No accounts, reminders, recurring items, field editing, external sync, production deployment, formal accessibility audit, or live database test evidence yet.

Learning

Setup is part of the user experience

For a non-technical audience, database creation cannot be a hidden prerequisite. Safe reruns, clear errors, relative demo dates, and copyable commands are product features.

Next priorities

Validate before expanding

Run live CRUD and browser accessibility tests first, then add item editing and reminders based on user feedback rather than broadening scope immediately.
