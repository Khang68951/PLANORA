01 / OVERVIEW

Planning without the technical friction.

Planora brings a dashboard, day/week/month calendar, task/deadline list, nested categories, and full project workspaces together in one responsive PostgreSQL-backed interface.

1Primary user type
4Core product views

Executive summary

One source of truth for plans and projects

The MVP relates tasks, deadlines, projects, members, documents, files, categories, AI conversations, and settings, then derives calendar placement, assignment, inherited categories, and urgency summaries. AI commands follow each project's approval mode, stay inside an allowlisted server boundary, and use recoverable soft deletion for destructive actions.

Current state

Working vertical slice

The optimized Next.js build passes. Local PostgreSQL provisioning and schema creation are automated, while live database smoke testing remains to be completed on a machine with Docker or PostgreSQL available.

02 / PROBLEM

Important dates disappear into scattered lists.

People need a simple visual answer to three questions: what is due, when is it due, and what needs attention now?

01

Primary user

A student or everyday planner who wants a calendar but should not need database, coding, or configuration knowledge.

02

Core friction

Separate task lists and calendars make urgency harder to see, while technical installation steps can make otherwise simple tools inaccessible.

03

MVP boundary

Single-user local planning is in scope. Accounts, sharing, reminders, recurring events, external sync, and production hosting are not yet included.

04 / CAPABILITIES

From a scattered deadline to a finished project.

Planora is more than a calendar. It connects capture, scheduling, organization, project materials, teamwork, AI assistance, and recovery so a non-technical user can move from "what do I need to do?" to "the work is complete" in one place.

01

Know what needs attention

Problem: urgent work is easy to miss inside a long list.

  • Dashboard counts overdue, upcoming, and completed work automatically.
  • Near-deadline cards bring the next actions forward without setup.
  • Tasks can be completed or reopened directly from the planner.

Outcome: the user opens Planora and immediately knows what to do first.

02

See time at the right scale

Problem: one calendar view cannot explain both today's work and a whole semester.

  • Switch between focused Day, Sunday-first Week, and six-week Month modes.
  • Tasks occupy their start-to-end interval; deadlines appear at one due time.
  • Select a date to start creating work and navigate by the active period.

Outcome: the same saved work supports daily focus and long-range planning.

03

Organize without hiding context

Problem: mixed personal, academic, and project work makes a planner noisy.

  • Manage colored classifications and compatible nesting from Settings, with a configurable default.
  • Use compact Calendar category/project controls and searchable multi-select inside the List filter drawer.
  • Search one toolbar, combine status/time/priority/project/PIC filters, remove chips, and choose eight sort modes.
  • Use up to three private category suggestions from a title and description.

Outcome: each view shows only the context needed there while the underlying records stay connected.

04

Run a complete project

Problem: plans, people, notes, and source files often live in unrelated tools.

  • Track project information, status, progress, dates, and upcoming work in Overview.
  • Add members and optional roles, then assign several people to one task or deadline.
  • Projects remain separate from standalone categories, with their own Calendar and List filters.

Outcome: the user can understand ownership, progress, and the next milestone from one workspace.

05

Keep thinking and evidence together

Problem: project notes and attachments become separated from the work they support.

  • Create sanitized rich-text document tabs with manual Save and Ctrl+S.
  • Receive a warning before internal navigation discards unsaved document changes.
  • Attach local files and preview images, PDFs, and supported text formats.

Outcome: decisions, drafts, and evidence stay beside the schedule they explain.

06

Delegate to AI without giving up control

Problem: an AI assistant is less useful if it cannot act, but unsafe if it can change everything silently.

  • Chat with project-specific context through Gemini, OpenRouter, or DeepSeek using server-only keys.
  • Use routed conversation and, only for actionable requests, an isolated planner with 24 allowlisted commands; one request appears as one compact approval group.
  • Choose Approve everything, Approve changes, or Auto; the backend builds the exact document result before it appears in place with highlighted human approval.

Outcome: AI can help create documents, plan work, update roles, and organize the project at the user's chosen trust level.

07

Recover from accidental removal

Problem: organizing work becomes risky when one mistaken delete can remove important plans.

  • Preview category-deletion impact and choose where affected standalone work should move.
  • Open Trash from the top bar and restore a complete related deletion batch together.
  • Choose Delete forever only inside Trash, then review a second popup that identifies the irreversible impact.
  • Permanently remove dependent project data and local attachments transactionally after explicit confirmation.

Outcome: users can reorganize confidently and recover without database knowledge.

08

Adapt the workspace to the user

Problem: a useful planner should not force every person into one visual or interaction style.

  • Choose Paper, Ocean, or Night appearance and a preferred Calendar mode.
  • Reduce motion and use responsive layouts across planner, project, review, and settings surfaces.
  • Close a project without changing it, then reopen it or create another workspace from the restored Projects page.

Outcome: Planora remains calm and usable across different screens and working habits.

09

Set up locally without database expertise

Problem: manual PostgreSQL installation, table creation, and seed entry would block the intended non-technical user.

  • Start PostgreSQL through Docker Compose with health checks and IPv4-safe local routing.
  • Run one idempotent setup command to create migrations, constraints, indexes, settings, and demo data.
  • Receive separate authentication, migration, and seed diagnostics when setup needs attention.

Outcome: installation is a documented terminal workflow, not a manual database-administration exercise.

A realistic Planora journey

1

Capture the commitment once

The user creates a task with a working interval or a deadline with one due time, adds priority and notes, and accepts a suggested or default category.

2

Plan it visually

The record immediately appears in Dashboard, Calendar, and Tasks & Deadlines. The user chooses a time scale, ticks only the relevant categories and projects, selects an entry to inspect or edit its populated fields, and selects empty day space to create new work for that date.

3

Turn it into coordinated project work

Inside a Project, the user records progress, assigns members, drafts a document, links source files, and sees upcoming work without leaving the workspace. Project tasks use project membership instead of a category label and immediately synchronize into Calendar and the main work list.

4

Ask AI to help, then keep authority

The AI can summarize readable files, create a proposal, break a goal into work, edit a document, or update members. One request becomes one compact approval group; its spacious review drawer shows every command, progress, group/individual decisions, and honest partial failures. Document approval remains beside the exact highlighted change.

5

Finish or recover safely

Completed work updates every view. Category removal shows impact and transactionally reassigns active work before only classifications enter Trash; destructive AI commands remain audited and recoverable.

C
Technical research

One server boundary, three provider choices

OpenRouter and DeepSeek use OpenAI-compatible chat completions, while Gemini uses Google's native streamed content endpoint. Each request enables the provider's JSON-output mode, but Planora still normalizes and semantically validates the result because valid JSON alone does not make a command safe. Keys stay out of client responses, and executable requests pass through an allowlisted command layer.

07 / METHODOLOGY

From a simple calendar idea to a complete planning workspace.

Planora grew in deliberate layers. Each extension kept the original promise—make tasks and deadlines understandable for a non-technical user—while solving the next problem revealed by the working product.

01

The first thought

A Canvas-like calendar for tasks and deadlines

The project began as a focused local planner: create or remove tasks and deadlines, see them on a calendar, keep a separate list, and use a dashboard to surface work that was near due or already late. PostgreSQL persistence, generated demo data, and terminal-only setup were part of the idea from the beginning because the target user should never create tables manually.

02

MVP foundation

One record, three useful views

The first vertical slice connected Dashboard, Calendar, and Tasks & Deadlines to the same validated PostgreSQL records. Task intervals, deadline due times, status, priority, editing, completion, relative demo dates, responsive states, Docker Compose, and repeatable migrations turned the concept into a working product instead of three disconnected mock-ups.

03

Organization extension

Categories became flexible, view-specific filters

Folder-like nested categories added naming, color, movement, visibility, depth settings, defaults, and private suggestions. Their filters moved from a global control to each relevant view: Calendar gained a compact Canvas-style right rail, while the task list gained searchable combined filters and sorting. Safe reassignment later replaced destructive category cascades.

04

Scheduling extension

Day, week, and month planning with personal settings

The original month calendar expanded into Day, Week, and Month modes with period-aware navigation and interval placement. Existing entries became visibly interactive and open their populated edit form, while empty day space still creates new work. Theme, default calendar mode, and reduced-motion settings made the experience adaptable without changing server data.

05

Project extension

Projects grew into their own workspace type

Projects were separated from standalone categories and expanded into a NotebookLM-inspired three-area workspace: navigation on the left, active content in the middle, and AI on the right. Overview, rich-text Documents, previewable Files, Tasks & Deadlines, Members, progress, dates, and multi-person PIC assignments now keep a complete body of work together and synchronize project work back to Calendar and the main list.

06

AI extension

Chat became a controlled project workflow

Provider chat evolved from a direct request into routed conversation plus an isolated command planner. Gemini, OpenRouter, and DeepSeek remain behind server-only keys. Scoped context, allowlisted commands, three approval modes, grouped runs, streamed responses, PIC commands, exact in-document highlighting, version checks, and explicit human approval let AI read and propose useful actions without direct database authority.

07

Safety and usability extension

Recovery, synchronization, and focused interaction

A visible top-bar Trash with grouped restoration and confirmed permanent deletion, unsaved-document warnings, optimistic chat, auto-growing composition, loading and error states, shared planner refresh, responsive overflow repairs, and a non-destructive Close Project action reduced the friction found while using the growing application. Project creation remains available from both an open workspace and the restored closed-project page.

08

Current evidence

A verified functional MVP with clear next steps

Eighty-four automated checks pass, ESLint completes cleanly, the optimized Next.js build compiles all application code and 27 API routes, and migration 006 has been applied successfully to PostgreSQL. Live provider, full browser, formal accessibility, and user-research evidence remain explicitly marked for future validation rather than being claimed without proof.

12 / REFLECTION

Be clear about limits and learning.

A strong report distinguishes what was achieved, what remains limited, what changed during development, and what should happen next.

Limitations

Local single-user MVP

No accounts, reminders, recurrence, collaborative editing, external sync, production deployment, formal accessibility audit, or live provider evidence yet. Database migration setup is verified, but destructive CRUD was not run against the user's existing records. Attachments require separate local backup, and AI reads text formats but not PDF/image contents.

Learning

Setup is part of the user experience

For a non-technical audience, database creation cannot be a hidden prerequisite. Safe reruns, clear errors, relative demo dates, and copyable commands are product features.

Next priorities

Validate before expanding

Add isolated-database API integration and browser accessibility tests, then validate grouped approval and responsive filtering with users before adding reminders or broadening scope.
